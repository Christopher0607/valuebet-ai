## 文件职责

```
backend/app/
  models.py     SQLAlchemy 数据表定义（9 张表）
  model.py      纯数学层：Dixon-Coles、贝叶斯更新类、EV/凯利、串关计算
                （不碰数据库，可以独立单元测试）
  updater.py    数据管道：抓取 → 归一化 → 入库 → 贝叶斯更新 → 跑预测 → 结算注单
  scheduler.py  APScheduler 定时任务（12 小时循环 + 启动立即跑一次）
  main.py       FastAPI 路由层

backend/training/
  train_mle.py             MLE 训练脚本（向量化 + 解析梯度）
  fitted_parameters.json   训练产出：261 支国家队的 attack/defense 参数
  historical_results.csv   训练输入：32,372 场国际比赛原始数据
```

## 关键设计决策（改动前请先理解这些）

### 1. EV 计算绝对不能用市场赔率反推概率

```python
EV = 我们模型的概率 × 市场原始赔率 - 1
```

**不是**"去除抽水后的市场概率 × 市场赔率"。后者是循环论证——拿市场跟市场自己比，EV 永远趋近 0，找不出任何优势。

这是项目最早期犯过、然后彻底重构掉的错误。如果有人提议"要不要先去掉庄家抽水再算 EV"，答案是**不需要，而且不能**——概率来自独立模型，赔率保持市场原始价格（那就是你实际能成交的价格），这才是正确的。

（抽水率作为**纯展示信息**是可以加的，让用户看到"这个盘口水位紧不紧"，但绝不能进 EV 公式。）

### 2. defense 参数的方向：数值越高 = 防守越强

模型公式是 `mu = exp(attack_away - defense_home)`，`defense` 以**减号**形式抑制对手进球率。

这个方向在开发过程中搞反过一次（详见 `04_BUGS_AND_LESSONS.md`），修复后写了多个方向性单元测试保护。**任何涉及 defense 参数的改动，请先跑一遍"零封后防守力应上升、大量失球后应下降"这类测试。**

### 3. 贝叶斯更新的参数化：更新 `theta = exp(-defense)` 而不是 `defense` 本身

因为泊松-伽马共轭要求被更新的量必须在模型公式里以乘性形式出现且服从泊松分布。`mu = exp(attack_away) × exp(-defense_home)`，所以 `theta = exp(-defense_home)` 才是那个该被共轭更新的量。

之前有一版为了"让方向看起来对"生造了 `1/(1+失球数)` 这个代理量，**那是错的**（不满足共轭前提），已经修掉。不要退回去。

### 4. 串关只支持跨比赛的独立事件

`/api/parlay` 会主动拒绝同一场比赛的两条腿。因为"西班牙赢"和"西班牙进球<1.5"是同一个泊松过程的两个切面，不独立，直接相乘算出来的概率是错的。同场比赛内的组合概率要用 `/api/score-distribution` 查真实联合分布。

### 5. 串关搜索只从正 EV 的腿里选

对独立事件 `EV_组合 = Π(1+EV_i) - 1`，任何 `EV_i < 0` 的腿都会拉低整体，哪怕它能把总赔率推得很好看。

这直接回应了用户最初的一个直觉（"把几个赔率低的强队串起来提高赔率"）——热门强队的赔率经常被市场压得低于其真实胜率对应的公平赔率（favorite-longshot bias，有实证文献支持），意味着这类"看起来很稳"的腿本身往往是负 EV。系统会直接把它们排除在候选池外，用真实计算告诉用户这一点。

### 6. 并发锁

`run_full_update()` 有 `threading.Lock`。因为调度器启动时会在后台线程立即跑一次更新，如果用户这时手动点"立即更新"，两个线程会在不同的数据库会话里同时"查询→插入"同一条记录，触发唯一约束冲突。这是真实发生过的 bug。

拿不到锁的调用会诚实返回 `{"status": "skipped", "detail": "..."}`，不排队、不静默失败。

### 7. `bayesian_folded_in` 标志

防止同一场比赛的结果被重复折算进贝叶斯后验。这也是真实 bug——之前反复点"立即更新"会让球队参数持续漂移，即使没有任何新比赛。

### 8. 队名归一化必须在入库前完成

`upsert_matches()` 里所有球队名都经过 `normalize_team_name()` 才写进数据库。这样保证：训练时用的球队名和实盘抓取时的球队名是同一套，贝叶斯状态的 key 能对上号。

如果哪天绕过这个函数直接写入原始队名，同一支球队会因为跨赛季命名差异被拆成两个实体，静默污染数据。
